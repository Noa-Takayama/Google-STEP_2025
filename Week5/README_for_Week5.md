# 巡回セールスマン問題ソルバー (TSP Solver)

## 概要

Week5 では、巡回セールスマン問題（TSP）を実装した。実装には、強力なヒューリスティック手法である**反復局所探索法 (Iterated Local Search, ILS)** を用いた。

## アルゴリズム

今回の `solver_ils.py` は、以下のアルゴリズムを組み合わせて最適な巡回路を探索する。

-   **反復局所探索法 (Iterated Local Search, ILS)**
    -   局所探索が局所に集中しすぎることなく、探索空間を広く探索するためのメタヒューリスティックである。
-   **局所探索 (Local Search)**: **2-opt法**
    -   経路上の2本の辺を交換し、経路長が短くなる場合は更新する操作を繰り返すことで、解を改善する。
-   **摂動 (Perturbation / "Kick")**: **Double Bridge法**
    -   局所最適解から脱出するために、経路に意図的に大きな変更を加える操作である。4本の辺を交換するこの操作は、2-opt法では到達しにくい解へのジャンプを可能にするという。

## 使い方

### 必要なもの

-   Python 3

### 実行方法

1.  ターミナルを開き, 以下のコマンドを実行する。

    ```bash
    # 書式: python solver_ils.py <入力ファイル> <出力ファイル>

    # 例: Challenge 4 (N=128) を解くならば
    python solver_ils.py input_4.csv output_4.csv
    ```

2.  実行後, 同じディレクトリに結果ファイル（例: `output_4.csv`）が保存される。

## 課題と改善の経緯

初期バージョン (`solver_ils.py`) では、特に大規模な問題 (Challenge 6: N=2048) において以下の課題があった.

### 課題：局所最適解と計算時間

-   **局所最適解への陥り**: ランダムな初期経路から開始する `solver_ils.py` では、質の低い局所最適解に囚われ、制限時間内にスコアが全く改善されないケースがあった.
-   **フィードバック不足**: 計算に最も時間を要する2-opt法の実行中に、プログラムが正常に動作しているかどうかのフィードバックがなく、進捗を把握するのが困難だった. 

### 改善

これらの課題を解決するため、2段階の改善を行ったのが `solver_ils2.py` 及び `solver_ils3.py` である.

#### 計算状況の可視化 (`solver_ils2.py`)

「フィードバック不足」の問題に対し、時間のかかる`local_search_2opt`関数の実行中に、1秒ごとに進捗を表示する機能を追加した.

**表示例:**
```bash
# 2-opt法の実行中に以下のような行が1秒ごとに更新され続ける
-> 2-opt search in progress... (Checking node i=152/2048)

### 局所最適解から逃げる (`solver_ils3.py`)

初期経路の生成方法をランダムなものから最近傍法に変更した.
これにより、探索の出発点が大幅に改善され、より質の良い最終解に到達する可能性が高まり、局所最適解に陥るリスクを低減できた.
